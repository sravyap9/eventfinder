# Security policy

## Reporting a vulnerability

Please do not open a public issue for a security problem. Use GitHub's private reporting instead: on the repository page open **Security**, then **Report a vulnerability**. If that is not available, open an issue that says only "security contact please" and no details.

This is a personal project run by one person, so there is no bounty and replies may take a few days, but reports are welcome and taken seriously.

## What is in scope

The two web pages (`index.html`, `v2/`), the build and data pipeline (`fetch.py`, `.github/workflows`), and the optional database setup (`supabase/schema.sql`). How the project defends itself, and what it cannot defend against, is described in [docs/SECURITY.md](docs/SECURITY.md).
